# SITE — technical notes: test shape per risk

Touchstone's rule, until `docs/engineering/test-strategy.md` exists: the risk's shape picks the test type. Touchstone, judgment.

## The gap

Today `yarn test` runs one smoke file under `node --test` (verified `package.json`, `tests/smoke.test.ts`). There is no browser runner, no accessibility scanner and no capture harness (`.claude/rules/testing.md`: "every `capture` criterion is UNVERIFIED"). The approved surfaces carry about 130 criteria; most of the `test` ones are keyboard, focus, ARIA and network behaviour that only a browser can show.

**Recommendation (routed, call C7):** the epic's first ticket adds `@playwright/test` (Chromium only) and `@axe-core/playwright` as exact-pinned dev dependencies, each with its `tech-stack.md` row (Quartermaster's seat, `.claude/rules/deps.md`), plus a capture script over every `?state=` key. Without it, those criteria can only be recorded as manual or UNVERIFIED.

## Rules for the builds

- All fixtures are synthetic and recognisably fake; never Micheal Ozdoba's words, never a real client's name beyond a published row title.
- Browser tests run against `yarn build:agent` and `yarn start:agent` (:4310), never port 3000.
- Flake is a defect: no retries in config; a flaky test is quarantined with an owner in its ticket.
- Playwright stays outside `yarn verify` until a later ticket decides the CI cost; each ticket names its Playwright commands as criteria scripts.
