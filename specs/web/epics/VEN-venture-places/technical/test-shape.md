# VEN — technical notes: test shape per risk

Touchstone's rule picks the test type from the shape of the risk: pure logic gets unit tests, combinatorial risk gets generated inputs, rendering gets end-to-end runs on the harness, and visuals get captures. `docs/engineering/test-strategy.md` does not exist yet (J11). Each criterion keeps the evidence type its surface file gave it. The scripts named here are what the Tickets stage writes into each criterion.

## The harness

- **Unit tests:** `tests/unit/intake-venture-*.test.ts`, under `yarn test`. They import `lib/intake/*` and `renderIntakeMarkdown` directly; `verify:tracks` already calls the renderer with no database.
- **End-to-end:** `tests/e2e/intake-venture.spec.ts` under `yarn test:e2e`, on `/test-harness/intake?state=<key>`, with the existing `tests/e2e/axe.ts` pass on every VEN key as a cheap floor.
- **Captures:** `yarn capture --route /test-harness/intake --keys <VEN keys> --out tests/.captures/ven`, scored by Assay.
- **Cartridge checks:** `yarn verify:tracks`, plus `yarn eval:primer --inventory` (both in `yarn verify` once C11 is ratified).
